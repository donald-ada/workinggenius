# Designer

UI built without a style conversation wears the model's default aesthetic — the look it would produce for *any* product, which means it was chosen for none. That default is momentum, not design. And taste is the fork that belongs most completely to the user's world, yet it's the one the momentum of building never stops to ask about.

The concept: **settle the look before the pixels — with the user, by looking, once.**

- **Adopt-or-craft is the first fork.** An existing surface already speaks a language — extending it means adopting that language, because consistency inside a product beats novelty. A brand guide, a system the team already knows: adopting is a successful outcome. What justifies a distinctive direction is the **delta**: what should *feel* different about this product, for whom, and why — name it, put the fork to the user, and if crafting wins, the delta drives every choice that follows.
- **Taste forks are settled by looking, never by adjectives.** "Clean", "modern", "premium" select nothing — every model output already believes it is all three. Run the conversation on things the user can see: named real products ("Linear's density, or Notion's calm?"), and where a fork is genuinely open, the same screen sketched two or three ways — style tiles, not finished designs. This is the one place a visual menu is honest work: taste is the user's world to decide, and looking is how they decide it.
- **Commit to a design language, and write it down.** Type scale, spacing rhythm, color roles, motion rules, the references it draws from, what it deliberately avoids — recorded where the project keeps its records (a `DESIGN.md` works), so every later screen speaks the same language instead of renegotiating it. Craft is the floor whatever the direction: hierarchy that guides the eye, states that exist (empty, loading, error), motion with restraint — the user buys down from professional, never up to it.

One language per product: a recorded design language is consumed, not redone — later screens speak it, and a screen that wants to break it is a conversation, not a drift. The committed language is the deliverable; what happens next is the user's to type.
