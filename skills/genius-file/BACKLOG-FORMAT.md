# The Backlog and Its Log

The cross-work files at `.genius/` — `BACKLOG.md` with `BACKLOG.log.md` behind it — have a format of their own, split out of [FILE-FORMAT.md](FILE-FORMAT.md) because a slice close never needs it: it is read by `/genius`, `/triage`, `/reconcile`, `/migrate` and `/distill`, and by whichever stage is about to route an Open line out as a seed. The seed's own shape and its 300-character bound are the `record-prose` skill's; what follows is the file's.

`BACKLOG.md` has a growth law of its own — **it grows by how many discoveries the flow made** — and until `BACKLOG.log.md` existed it had no way to shrink. The per-line bound (`record-prose` holds it and its why) was never a bound on the file. Measured on one real project, counted the way FILE-FORMAT's measure section counts, sixteen commits took it from 748 to 10062 characters without one of them leaving the file smaller than it found it.

So it gets the same two-file shape a work gets, and the same invariant: **nothing leaves `BACKLOG.md` except into `BACKLOG.log.md` or into the work file it became, and a link is left behind wherever there is still a line to carry it.** `BACKLOG.log.md` sits beside it at `.genius/`, is append-only, and is created at its first entry, not before — a backlog with no log beside it is this format waiting for its first displacement, exactly as with a work's log (FILE-FORMAT). Links from either file are relative to `.genius/`, like the other cross-work files (FILE-FORMAT's link rule). An entry's key is a short descriptive slug plus the date, `<slug>-<date>` — `stale-vpp-tooltip-2026-08-29` is one whole key — where a work's log date-suffixes only on collision: a seed can be corrected, merged and retired across months, and those are the same seed, so the key cannot be unique by construction the way a numbered slice is. The seed points at one with `[detail](BACKLOG.log.md#<slug>-<date>)`.

That turns three moves that were previously deletions into routing:

- **Retire** — a seed whose work is done, or whose reason stopped holding. The body goes to the log with what retired it; the line goes. This is the destination `errata`'s Retire had no name for here.
- **Merge** — two seeds that are one discovery, and merging is what stops the same finding being re-argued from two places. Both bodies go to the log verbatim; one seed remains, carrying both links. ⚠ A seed that says *why it must stay separate* is not a merge candidate, whatever it shares with its neighbour. And the surviving seed still obeys the per-line bound — **two seeds that cannot say their one discovery inside one line were not one discovery**, or they are a piece of work; either way the merge is the wrong move.
- **Correct** — the seed is rewritten in place; the old wording and what overturned it are appended (the same move `errata` names, applied here).

Retire, like the snapshot's Open drain (FILE-FORMAT), is the case where the line itself is what leaves, so no link can survive in its own place. It moves up one level exactly as draining does: **`BACKLOG.md` carries `[retired](BACKLOG.log.md#<slug>-<date>)` at its foot, one per retirement, never one accumulating them** — the log is append-only, so each retirement is its own dated entry and no later one can be filed under an earlier anchor. A retirement whose link got overwritten is text nobody can reach, which is the hole `errata` warns reads exactly like a stage that never ran.

**Starting the work is the fourth way a line leaves, and the one that writes no log entry**: the line goes because the new work file is its home now (the `genius-file` skill carries that rule), and that file — listed by `ls .genius/`, opened by every status view — holds what the seed was pointing at. Nothing is lost *if the work really took the seed's content up* — measured once and found false in one case, where a seed's stated rule reached no section of the work that absorbed it, so check that before letting the line go and land whatever the work missed where the builder reads. ⚠ **The line between this and Retire is which came first.** A seed that *became* the work leaves this way. A seed an already-running work absorbed on its way past is retired, with the absorbing work named as what retired it — because there the work file was never that seed's home, and without the log entry nothing records that the seed was answered rather than forgotten.

⚠ **Trimming a seed displaces text even though the line stays**, so it lands here like anything else that leaves the file — unless the seed's own link already names a log entry that holds the detail, in which case it goes there and the seed keeps pointing where it always did. Two destinations, one rule: text follows the pointer that will be looked for, and a seed whose provenance was never a link has only one place to leave to.

⚠ **`BACKLOG.log.md` is not a third exit from the snapshot either.** An Open item that is work in its own right still routes through *its own work's* log, with the seed pointing there (the rule above). This log takes only what leaves `BACKLOG.md` itself — which is what makes it always available: a seed whose provenance was never a link, and a seed whose absorbing work has no log, both have somewhere to leave to.

**Order is the file's own statement of what to do next** — top to bottom. A new seed is appended at the bottom, where "not yet placed" is what its position honestly says; reordering is a deliberate write, one line at a time, not a pass that silently re-sorts. On one real file that weight is being carried by the prose instead — seeds whose own text says which of them must not wait for the other — and that is the reason to settle it in the position rather than to leave it in both: two encodings of one order drift, and the reader cannot tell which one is current. An order nobody maintains is a lie the next reader believes.

⚠ **The cross-work files are not a piece of work, whatever their shape.** `BACKLOG.md` with `BACKLOG.log.md` beside it matches flat two-file work exactly (FILE-FORMAT's rules name that shape), so every pass that reads shape rather than names — `/migrate` above all, and anything else that recognises a work by its files — is excluded here rather than one at a time: `.genius/`'s own files are never migrated into a folder, and they are no *work's* log — so a pass that sweeps works' logs does not reach them, though they are record layer like any log and `errata` treats them so. They span works; a folder would say they belong to one, and a sweep that deletes by work would delete what every work still points through.
