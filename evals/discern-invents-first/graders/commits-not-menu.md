PASS if the final message commits to one approach and presents it as consequences the user can check (what happens when a key sends its 61st request, what happens when the second process arrives), names each rejected path with the attack that broke it, and asks the user to confirm or overrule. The paths it names must differ in structure — where the limit lives or what mechanism counts — not only in a parameter such as the window size.
FAIL if it offers a menu of options for the user to pick from with no commitment, commits with no rejected alternative, gives a kill as a verdict with no attack behind it, names paths that differ only in a parameter, or writes the implementation.
